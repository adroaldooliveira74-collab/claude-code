USO INTERNO — VENDEDOR

Guia do Vendedor

Como vender, licenciar e manter o Perito · Laudo. Não distribua este arquivo.

1. O que você entrega ao cliente

Apenas o venda-pericia.zip (EXE + APK + Manual). Ele é montado sozinho pelo GitHub Actions a cada atualização (aba Actions → Pacote de Venda → Artifacts → venda-pericia).

Nunca entregue: a chave privada, o Gerador-de-Licencas.html, a pasta ferramentas/ ou este guia.

2. Gerar o código de liberação (12 meses)

  1. Abra o Gerador-de-Licencas.html.
  2. Cole a sua chave privada (arquivo MINHA-CHAVE-PRIVADA.txt).
  3. Digite o nome do cliente, deixe 12 meses e clique Gerar.
  4. Copie o código e envie ao cliente. Ele ativa em Painel de Controle → Ativar (ou na tela Assinar/Renovar).

Renovação: gere um novo código de 12 meses quando o cliente renovar.

3. Preço, PIX e WhatsApp (tela de compra)

Edite o arquivo venda-config.js com os seus dados antes de publicar o pacote:

window.VENDA = {
  preco:   "R$ 1.200,00 por ano",
  pix:     "sua-chave-pix",
  pixTitular: "Seu Nome",
  whats:   "5544999999999",   // DDI+DDD+numero, só dígitos
  email:   "seu@email.com"
};

A tela Assinar/Renovar (dentro do programa) mostra o plano, o PIX (com botão copiar) e um botão de WhatsApp já com mensagem pronta. O cliente paga, manda o comprovante e você envia o código.

4. Teste grátis e modo consulta

  • 7 dias grátis na primeira execução (uso completo).
  • Depois, sem licença válida → modo consulta (abre e lê, mas não edita/gera documentos).
  • Ao ativar um código válido → tudo liberado por 12 meses.

Para mudar a duração do teste, edite TRIAL_DAYS em comercial.js.

5. (Opcional) Assinar o .exe — tira o aviso do Windows

Com um certificado de assinatura de código (pago, ex.: Sectigo/DigiCert), o .exe sai assinado e o Windows para de mostrar “Executar assim mesmo”.

  1. Compre o certificado (.pfx) e sua senha.
  2. No GitHub: Settings → Secrets and variables → Actions → New secret:
    • WINDOWS_CERT_BASE64 = conteúdo do .pfx em base64
    • WINDOWS_CERT_PASSWORD = a senha do .pfx
  3. Pronto: o próximo build do pacote já sai assinado (o workflow venda.yml usa esses secrets automaticamente). Sem os secrets, compila normal.
Para gerar o base64 do .pfx no PowerShell:
[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx")) | Set-Clipboard

6. (Opcional) Ativação online — anti-compartilhamento

Limita quantos computadores usam o mesmo código e permite revogar à distância. A emissão continua offline (o servidor não guarda a chave privada).

  1. Hospede server/licenca-online.js em qualquer serviço Node (VPS, Render, Railway…). Ele sobe com: 
    ADMIN=suasenha MAX_DEVICES=2 node server/licenca-online.js
  2. No pacote, crie um arquivo online-config.js com window.VP_ONLINE_URL="https://seu-servidor"; e carregue-o nas páginas (antes de comercial.js).
  3. Revogar um código: 
    POST /revogar  cabeçalho x-admin: suasenha  corpo: {"token":"<codigo>"}
    (para reativar, envie {"token":"...","liberar":true}).
Sem hospedar o servidor nem definir a URL, o programa funciona 100% offline como hoje — a ativação online é um extra.

7. Segurança (seja realista com o cliente)

  • A licença offline já segura o uso casual, mas não é 100% à prova de pirataria. Para blindar, ligue a ativação online (item 6).
  • Guarde a chave privada em local seguro e com backup. Se perder, não consegue gerar novos códigos; se vazar, qualquer um gera.
